# Case Studio

Where instructors write cases for the app (#20). Cases are kept as drafts, checked with the app's own
rules, and exported together as one case package (`../contract/`) that the app imports. The app never
contacts the studio: cases reach phones only as the exported file.

Stack (the suite's): Go with SQLite (`modernc.org/sqlite`, no cgo), goose migrations, sqlc; an Angular 22
web app (standalone components, signals, zoneless, Tailwind 4) embedded in the one binary.

## Layout

| Path | What |
|---|---|
| `backend/cmd/casestudio/` | The program: `serve` (default), `migrate`, `version` |
| `backend/db/migrations/`, `backend/db/queries/` | Schema (goose, embedded, applied at every start) and queries (sqlc) |
| `backend/internal/cases/` | The app's case rules ported from `mobile/lib/game/` with the same problem texts; `contract_test.go` runs `../contract/examples/verdicts.json` |
| `backend/internal/drafts/` | The drafts' API |
| `backend/internal/auth/` | Sign-in (a JWT in an httpOnly cookie, bound to the password), CSRF, throttling, the accounts |
| `backend/internal/store/` | Generated by sqlc: never edit by hand |
| `backend/internal/web/` | Serves the web app built into `dist/` (only its README is committed; without a build `/` says so) |
| `frontend/src/app/` | The web app: `list/` (the drafts), `editor/` (one case), `account/` (sign-in, password), `users/` (accounts), `case/` (JSON paths, blank shapes, the words for places), `api/`, `ui/` |
| `frontend/public/` | Links to the app's equipment pictures, fonts (with their licence) and icons in `mobile/`: one copy, the app's |
| `frontend/tests/` | Playwright: `unit/` guards (no browser), `e2e/` against the real binary |
| `dev/build.sh` | The one program with the web app embedded |
| `dev/check.sh` | The gate |

## Commands

```sh
export GOTOOLCHAIN=go1.27.3            # this machine's go is older; go.mod says 1.27.3
dev/build.sh /tmp/casestudio           # the program with the web app in it
read -rs PW && printf '%s\n' "$PW" | /tmp/casestudio user add <username> --name "<name>" --admin   # the first admin
/tmp/casestudio                        # then open http://127.0.0.1:5310 and sign in
dev/check.sh                           # the gate: Go, Prettier, ng build (0 warnings), Playwright, the app's contract tests

# while working on it: the API, and the web app with live reload
(cd backend && go run ./cmd/casestudio)          # API on 127.0.0.1:5310, data in backend/data
(cd frontend && pnpm install && pnpm start)      # http://localhost:4200, /api passed to 5310
(cd frontend && pnpm test:unit)                  # the guards, in a second
(cd frontend && pnpm test:e2e)                   # builds the binary, a fresh server per test
(cd backend && go tool sqlc generate)            # after changing db/queries or db/migrations
```

Settings: `CASESTUDIO_ADDR` (default `127.0.0.1:5310`), `CASESTUDIO_DATA` (default `./data`: the database
and `session.key`, the key sessions are signed with, made at the first start; a new key signs everyone out).

## Sign-in and accounts

- **Only instructors sign in; nobody signs up.** An admin adds each account (on the screen บัญชีผู้ใช้, or
  `casestudio user add`), tells the person their first password, and they change it themselves. The first
  admin is added with the command; `casestudio user password <username>` sets a lost one.
- **Drafts are shared:** every instructor sees and edits every draft, because a package is one ward's set
  of cases (an import replaces all the cases in the app). The version check keeps two people from saving
  over each other unseen, and each draft says who saved it last.
- An account is switched off, never deleted, and its session ends at its next request; a password change
  ends every other session of the account. Passwords: at least 10 characters, not the username, not a
  common one (argon2id). After five wrong passwords for one username from one address, it waits up to 15 minutes.
- A session lasts 12 hours without use. When it ends while a page is open, a sign-in dialog opens over
  the page: unsaved edits stay, and the person repeats what they were doing.
- Writes must come from the studio's own page (CSRF double submit, Origin checked). Behind HTTPS the cookies
  are sent over HTTPS only: directly, or through a reverse proxy on the same machine that sets
  `X-Forwarded-Proto: https` (the only proxy whose headers are believed).

## The web app

The words on screen are Thai, like the app's (his case manager's labels where he had one); each field also
shows its key in the case JSON. Problem texts are the server's, in English, word for word as the app
writes them.

| Screen | What |
|---|---|
| เคสทั้งหมด (`/`) | Every draft: bed, title, ready or how many problems, last saved and version. New case, import a file (a package, the app's export or his React app's), export the package, copy, delete |
| แก้ไขเคส (`/drafts/{id}`) | Tabs: the case's fields, each step (name, mechanic, reading, the doctor's line, vitals, and its tasks: choices, sequence, trays, unordered drop, with their cards, pictures and answers), and the whole case as JSON |

- **Problems sit on their fields.** The server's paths (`$.stageData[1].traysTask.pool[2].img`) name the
  place; each field shows the problems at its path, and the list at the top opens the tab and puts the
  cursor there. The e2e tests check this for every contract example with exact problem lines.
- **Checked as you type:** every change goes to `POST /api/check` a moment after the last keystroke;
  nothing is saved until Save (or Ctrl+S).
- **Save with the version it was opened at.** Someone else's save since then refuses it (409): the page
  says so and offers the latest version; a draft deleted meanwhile can be saved as a new one. Leaving with
  unsaved changes asks first.
- **Only what you change changes:** opening and saving a case keeps its JSON as it was, keys the form
  does not show included. Renaming a card's id renames it in the order and tray lists of its task.
- The form keeps the case as plain JSON (not Angular forms), so a case with a wrong type from an imported
  file still opens: the field shows the value and the problem, and the JSON tab fixes what the form cannot.

## API

Every route needs a signed-in account except `GET /api/meta`, `GET /api/auth/session`, `POST
/api/auth/signin` and `POST /api/auth/signout`; `/api/users` needs an admin.

| Route | What |
|---|---|
| `GET /api/meta` | Package format and version, steps per case, the app's equipment pictures |
| `GET /api/auth/session` | `{"user": ...}` or `{"user": null}`, and the page's CSRF cookie |
| `POST /api/auth/signin` `{"username", "password"}` | Sign in; `401 wrong`, `403 inactive`, `429 throttled` |
| `POST /api/auth/signout` | Sign out |
| `PUT /api/auth/password` `{"current", "next"}` | Change one's own password |
| `GET /api/users`, `POST /api/users` | The accounts; add one `{"username", "name", "password", "admin"}` |
| `PUT /api/users/{id}` `{"name", "admin", "active"}`, `PUT /api/users/{id}/password` | Change an account, set its password |
| `GET /api/drafts` | Every draft: bed, title, version, who saved it last, number of problems |
| `POST /api/drafts` `{"case": {...}}` | A new draft (it may be unfinished) |
| `GET /api/drafts/{id}` | One draft with its problems (`path`, `message`) |
| `PUT /api/drafts/{id}` `{"version": n, "case": {...}}` | Save; refused with `409 stale` if someone saved since version `n` |
| `DELETE /api/drafts/{id}?version=n` | Delete, with the same check |
| `POST /api/check` `{"case": {...}}` | The problems of a case, without saving |
| `POST /api/import` (body: the file) | Every case of a package or an older case file, as new drafts |
| `GET /api/package` | Every draft as one package, only if the app would accept it; else `422` with the problems |

Refusals are `{"detail", "code", "problems"}`. A draft's id is never given out again after a delete, so a
save from a page still open on a deleted draft cannot land on a new one.

## Clinical content

The rules only check that a case can be played. Whether its content is clinically right is the clinical
reviewer's call; the studio never fills in clinical content (a new case starts blank).
