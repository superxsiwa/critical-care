# Case Studio

Where instructors write cases for the app (#20). Cases are kept as drafts, checked with the app's own
rules, and exported together as one case package (`../contract/`) that the app imports. Since step 10
(2026-11-06) an instructor can also **publish** the drafts: the app follows the newest published revision
through the studio's public, read-only feed, and plays it offline. A file export still works as before.

Stack (the suite's): Go with SQLite (`modernc.org/sqlite`, no cgo), goose migrations, sqlc; an Angular 22
web app (standalone components, signals, zoneless, Tailwind 4) embedded in the one binary.

## Layout

| Path | What |
|---|---|
| `backend/cmd/casestudio/` | The program: `serve` (default), `migrate`, `version` |
| `backend/db/migrations/`, `backend/db/queries/` | Schema (goose, embedded, applied at every start) and queries (sqlc) |
| `backend/internal/cases/` | The app's case rules ported from `mobile/lib/game/` with the same problem texts; `contract_test.go` runs `../contract/examples/verdicts.json` |
| `backend/internal/drafts/` | The drafts' API |
| `backend/internal/catalog/` | The equipment names and the knowledge articles (the studio's own, never in the package) |
| `backend/internal/auth/` | Sign-in with Google (`google.go`, OpenID Connect) or a password, the session (a JWT in an httpOnly cookie, bound to the account's credentials), CSRF, throttling, the accounts |
| `backend/internal/store/` | Generated by sqlc: never edit by hand |
| `backend/internal/web/` | Serves the web app built into `dist/` (only its README is committed; without a build `/` says so) |
| `frontend/src/app/` | The web app: `board/`, `case-library/`, `case-mg/` (the drafts), `editor/` (one case), `equipment/`, `knowledge/`, `account/` (sign-in, password), `users/` (accounts), `case/` (JSON paths, blank shapes, the words for places), `api/`, `ui/` |
| `frontend/public/` | Links to the app's equipment pictures, fonts (with their licence) and icons in `mobile/`: one copy, the app's |
| `frontend/tests/` | Playwright: `unit/` guards (no browser), `e2e/` against the real binary |
| `dev/build.sh` | The one program with the web app embedded |
| `dev/check.sh` | The gate |

## Commands

```sh
export GOTOOLCHAIN=go1.27.3            # this machine's go is older; go.mod says 1.27.3
dev/build.sh /tmp/casestudio           # the program with the web app in it
read -rs PW && printf '%s\n' "$PW" | /tmp/casestudio user add <username> --name "<name>" --admin   # the first admin
/tmp/casestudio                        # then open http://127.0.0.1:5310 and sign in
dev/check.sh                           # the gate: Go, Prettier, ng build (0 warnings), Playwright, the app's contract tests

# while working on it: the API, and the web app with live reload
(cd backend && go run ./cmd/casestudio)          # API on 127.0.0.1:5310, data in backend/data
(cd frontend && pnpm install && pnpm start)      # http://localhost:4200, /api passed to 5310
(cd frontend && pnpm test:unit)                  # the guards, in a second
(cd frontend && pnpm test:e2e)                   # builds the binary, a fresh server per test
(cd backend && go tool sqlc generate)            # after changing db/queries or db/migrations
```

Settings: `CASESTUDIO_ADDR` (default `127.0.0.1:5310`), `CASESTUDIO_DATA` (default `./data`: the database
and `session.key`, the key sessions are signed with, made at the first start; a new key signs everyone out).

Google sign-in is on when `CASESTUDIO_GOOGLE_CLIENT_ID` is set (with `CASESTUDIO_GOOGLE_CLIENT_SECRET`): a
Google Cloud OAuth client of type Web application whose redirect URI is `<address>/api/auth/google/callback`.
`CASESTUDIO_PUBLIC_URL` is that address (`https://studio.criticalcare.212cafe.com`; without it, the request's
own address). On the server the three are in the service's environment file, readable by the service only.
`CASESTUDIO_GOOGLE_ISSUER` points the tests at a fake Google. Without a client id, passwords only.

## Sign-in and accounts

- **Two types of account, Admin and พยาบาล (nurse); nobody signs up.** Both write and manage cases;
  only an Admin manages the accounts. An admin adds each account (on the screen บัญชีผู้ใช้, or
  `casestudio user add`) with the person's Google email, a fallback password, or both. The first admin is
  added with the command; `casestudio user password <username>` sets a lost password, `casestudio user
  email <username> <email>` an email.
- **Google sign-in is the default; the password is the fallback.** A person's first Google sign-in with
  the account's email (verified by Google) ties the account to their Google account, which later sign-ins
  match even if the email changes. A Google account that matches no account is refused: nobody signs up
  through Google either. An account may have no password (Google only); signed in with Google, the person
  sets a fallback on the password page. A new email, or untying Google (a replaced Google account), unties
  it and ends the account's sessions. While the Google client is in Testing, Google also lets in only its
  listed test users.
- **Drafts are shared:** every instructor sees and edits every draft, because a package is one ward's set
  of cases (an import replaces all the cases in the app). The version check keeps two people from saving
  over each other unseen, and each draft says who saved it last.
- An account is switched off, never deleted, and its session ends at its next request; a password change
  ends every other session of the account. Passwords: at least 10 characters, not the username, not a
  common one (argon2id). After five wrong passwords for one username from one address, it waits up to 15 minutes.
- A session lasts 12 hours without use. When it ends while a page is open, a sign-in dialog opens over
  the page: unsaved edits stay, and the person repeats what they were doing.
- Writes must come from the studio's own page (CSRF double submit, Origin checked). Behind HTTPS the cookies
  are sent over HTTPS only: directly, or through a reverse proxy on the same machine that sets
  `X-Forwarded-Proto: https` (the only proxy whose headers are believed).

## The web app

The words on screen are Thai, like the app's (his case manager's labels where he had one); each field also
shows its key in the case JSON. A problem reads in Thai where there is a Thai wording for it, followed by
the server's English text in brackets, word for word as the app writes it.

A header with the account menu (profile, change password, sign out), a menu on the left, the page on the
right. Every page but sign-in loads when first opened.

| Screen | What |
|---|---|
| Board (`/`) | Counts (cases, ready, with problems, equipment pictures), a tile per bed, the latest cases |
| คลังเคส (`/case`) | Every draft to read: find by title, bed or who saved it, filter ready / with problems, as a list or cards |
| คลังอุปกรณ์ (`/equipment`) | The app's equipment pictures with their names (from the server), by category |
| คลังความรู้ (`/knowledge`) | Articles for authors (from the server), by folder, list or cards |
| จัดการเคส (`/case-mg`) | Every draft: bed, title, ready or how many problems, last saved and version. New case, import a file (a package, the app's export or his React app's), export the package, **ประกาศใช้ในแอป (publish to the app)** with what the app follows now (revision, cases, when, by whom), copy (opens the copy), delete |
| จัดการคลังความรู้ (`/knowledge-mg`), จัดการอุปกรณ์ (`/equipment-mg`) | Add, change and delete articles and equipment names, kept on the server (shared, like drafts; a change from a page opened before someone else's is refused and keeps what was typed). An equipment entry names one of the app's own pictures, one entry per picture, and its picture never changes: a new entry can only name a picture whose entry was deleted. **None of it goes into the package** |
| แก้ไขเคส (`/drafts/{id}`) | Tabs: the case's fields, each step (name, mechanic, reading, the doctor's line, vitals, and its tasks: choices, sequence, trays, unordered drop, with their cards, pictures and answers), and the whole case as JSON. A bedside preview of the open step's monitor and the doctor's line; a step can be copied; MAP can be filled from BP and a missing % added to SpO2, each only when its button is pressed |
| บัญชีผู้ใช้ (`/users`) | Admin only: add an account (Admin or พยาบาล), change it, switch it off, set its password |

- **Problems sit on their fields.** The server's paths (`$.stageData[1].traysTask.pool[2].img`) name the
  place; each field shows the problems at its path, and the list at the top opens the tab and puts the
  cursor there. The e2e tests check this for every contract example with exact problem lines.
- **Checked as you type:** every change goes to `POST /api/check` a moment after the last keystroke;
  nothing is saved until Save (or Ctrl+S).
- **Save with the version it was opened at.** Someone else's save since then refuses it (409): the page
  says so and offers the latest version; a draft deleted meanwhile can be saved as a new one. Leaving with
  unsaved changes asks first.
- **Only what you change changes:** opening and saving a case keeps its JSON as it was, keys the form
  does not show included. Renaming a card's id renames it in the order and tray lists of its task.
- The form keeps the case as plain JSON (not Angular forms), so a case with a wrong type from an imported
  file still opens: the field shows the value and the problem, and the JSON tab fixes what the form cannot.

## API

Every route needs a signed-in account except `GET /api/meta`, `GET /api/auth/session`, `POST
/api/auth/signin`, `POST /api/auth/signout`, the two Google routes and the app's feed (`/api/published`);
`/api/users` needs an admin.

| Route | What |
|---|---|
| `GET /api/meta` | Package format and version, steps per case, the app's equipment pictures |
| `GET /api/auth/session` | `{"user": ..., "google": true}` (`"user": null` signed out; `"google"`: Google sign-in is on), and the page's CSRF cookie |
| `POST /api/auth/signin` `{"username", "password"}` | Sign in; `401 wrong`, `403 inactive`, `429 throttled` |
| `GET /api/auth/google/start?next=&popup=` | To Google (state, nonce and PKCE verifier in a signed 10-minute cookie) |
| `GET /api/auth/google/callback` | From Google: signed in and on to `next` (the popup: `/signin/done`), else `/signin?google=<why>` |
| `POST /api/auth/signout` | Sign out |
| `PUT /api/auth/password` `{"current", "next"}` | Change one's own password |
| `GET /api/users`, `POST /api/users` | The accounts; add one `{"username", "name", "email", "password", "admin"}` (an email, a password, or both) |
| `PUT /api/users/{id}` `{"name", "admin", "active"}`, `PUT /api/users/{id}/password` | Change an account, set its password |
| `PUT /api/users/{id}/email` `{"email"}`, `DELETE /api/users/{id}/google` | Set its Google email (unties Google), untie Google |
| `GET /api/drafts` | Every draft: bed, title, version, who saved it last, number of problems |
| `POST /api/drafts` `{"case": {...}}` | A new draft (it may be unfinished) |
| `GET /api/drafts/{id}` | One draft with its problems (`path`, `message`) |
| `PUT /api/drafts/{id}` `{"version": n, "case": {...}}` | Save; refused with `409 stale` if someone saved since version `n` |
| `DELETE /api/drafts/{id}?version=n` | Delete, with the same check |
| `POST /api/check` `{"case": {...}}` | The problems of a case, without saving |
| `POST /api/import` (body: the file) | Every case of a package or an older case file, as new drafts |
| `GET /api/package` | Every draft as one package, only if the app would accept it; else `422` with the problems |
| `POST /api/publish`, `GET /api/publish` | Publish every draft to the app as the next revision, checked as the export (`422 empty`, `422 not-ready` with the problems); the revisions, newest first, with who published them |
| `GET /api/published` | **Public, for the app:** the newest revision `{"revision", "publishedAt", "cases", "package"}` (no names), `404 none` before the first; never cached; `Access-Control-Allow-Origin: *` |
| `GET /api/published/{revision}` | **Public:** that revision's package, byte for byte: a version 1 package that also says `revision` and `publishedAt`. A revision never changes, so it is cached for good |
| `GET /api/equipment` | The equipment names, one per picture of the app: `id`, `file`, `nameTh`, `nameEn`, `category`, `version`, who changed it last |
| `POST /api/equipment` `{"file", "nameTh", "nameEn", "category"}` | Name a picture; `422 picture-unknown` (not one of the app's pictures), `409 picture-taken` (it has a name) |
| `PUT /api/equipment/{id}` `{"version", "nameTh", "nameEn", "category"}`, `DELETE /api/equipment/{id}?version=n` | Change (the picture stays) or delete; `409 stale`, `404` as for drafts |
| `GET /api/knowledge`, `POST /api/knowledge` `{"title", "category", "summary", "content"}` | The knowledge articles; add one |
| `PUT /api/knowledge/{id}` `{"version", ...}`, `DELETE /api/knowledge/{id}?version=n` | Change or delete an article, with the same check |

Refusals are `{"detail", "code", "problems"}`. A draft's id is never given out again after a delete, so a
save from a page still open on a deleted draft cannot land on a new one; the same holds for equipment
entries and articles. The equipment names and articles were seeded once (migration 00005) from the lists
built into his pages; a title, name or category may not be empty or longer than 200 characters.

## Clinical content

The rules only check that a case can be played. Whether its content is clinically right is the clinical
reviewer's call; the studio never fills in clinical content (a new case starts blank). The same goes for
the knowledge articles (the MAP article's formula and ranges among them): the studio keeps them as written.
